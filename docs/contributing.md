# Contributing

Read [repository-layout.md](repository-layout.md) first — it answers "where
does my code go?", which is the question most changes hinge on.

Before pushing:

```bash
npm run check   # paths + boundaries + typecheck + tests
```

## Adding a reusable package

1. Create `packages/<name>/` with a `package.json` named `@av/<name>`.
2. Add the path to `workspaces` in the root `package.json`.
3. Register it in `compose.config.json` under `components`, declaring its
   `capabilities` and `requires`, and set `"standalone": true`.
4. Add it to whichever `profiles` should include it.
5. Run `node tools/gen-docs.mjs` to generate its reference page.
6. `bun install`.

Do not import anything from `studio/` — that is what makes it a package rather
than a module. `check:boundaries` will tell you immediately.

## Adding a capability

Capabilities are provider-neutral (ADR-0015). A stage asks for
`speech.synthesize`; it never asks for a particular vendor.

1. Add the name to the canonical vocabulary in `studio/contracts`.
2. Declare it in `compose.config.json` on the component that provides it.
3. Wire the studio-side call in `studio/agent`.

Exactly one component may claim a capability in a given profile. If two do,
`compose` fails rather than picking a winner — resolving that is an editorial
decision, not a tooling one.

## Adding a skill

- Reusable technique → `skills/shared/`
- Production stage → `skills/studio/`

`skills/` is the source of truth; `.pi/skills/` is generated by `compose`
(ADR-0029). Never edit `.pi/skills/` — the next compose overwrites it.

## Adding or changing a pipeline

Pipeline manifests live in `studio/pipelines/pipelines/`. They validate against
the canonical schema owned by `studio/contracts` (ADR-0024) — this package does
not define its own.

```bash
npm run lint:pipeline --workspace @studio/pipelines -- pipelines/*.yaml
```

## Dependencies

Use `workspace:*` for anything inside this repository. **Never `file:../`** — it
installs as a symlink holding an absolute path, which is how the predecessor
layout became uninstallable on every machine but one. `check:paths` fails the
build if an absolute path reappears.

Reach for a package by name, never by relative path. `../../other/src/thing.ts`
is a boundary violation even when it happens to resolve.

## Documentation

- Component reference pages under `docs/packages/` and `docs/studio/` are
  **generated** — edit `compose.config.json` or the component's own README and
  `docs/`, then run `node tools/gen-docs.mjs`.
- Everything else in `docs/` is hand-written.
- A decision that constrains future work gets an ADR in `docs/adr/`.
