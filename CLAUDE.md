# Agentic Video Studio

This repository is two things, and a session here is usually one of them:

- **The code** of the studio: reusable media packages (`packages/`), the
  product built on them (`studio/`), and the skills its agent uses (`skills/`).
- **The studio itself**, run from the repository root: an agent produces
  narrated, illustrated videos in the library (`library/`, a link to the
  production data; never committed).

## Producing video

The studio's tools come from the `pva` MCP server, which `.mcp.json` starts
(`studio/agent/mcp/server.ts`). It serves the same tools Pi gets from
`studio/agent/extensions/index.ts`, unchanged, as `mcp__pva__pva_*`; the slash
commands are its prompts (`/mcp__pva__video`, `/mcp__pva__render`, …).

- Before production work, load the `pva-executive-producer` skill; each stage
  has its own skill (`write-brief`, `write-script`, `compose-video`, …).
- Paid generation is budgeted per episode: `pva_budget_status` before spending.
- Only the operator approves a stage. Ask with `pva_request_approval`; never
  approve on their behalf.
- Generated media stays in the library, never in git (ADR-0021).

Start `claude` from the repository root: the server finds the library and
`tsx` from there. [docs/running.md](docs/running.md) covers the rest,
including Pi, the gateway and the browser studio.

## Changing the code

Read [docs/repository-layout.md](docs/repository-layout.md) first, then
[docs/contributing.md](docs/contributing.md).

- `packages/*` never import from `studio/` (`npm run check:boundaries`).
- The agent's tools are written once, against Pi's extension API, in
  `studio/agent/src/`. Pi loads them directly; the MCP server hosts the same
  registrations (`studio/agent/mcp/host.ts`). Do not fork a tool per harness.
- Skills are edited in `skills/` and `studio/agent/skills/`; `.pi/skills/` and
  `.claude/skills/` are generated by `npm run compose`.
- Before pushing: `npm run check`.
